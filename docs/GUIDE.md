# 🧭 저장소 사용 가이드

이 문서는 **폴더/파일 규칙, 커밋·PR 방법, 풀이 작성법**을 설명합니다.

---

## 1. 폴더 & 파일 규칙

### 풀이 위치
```
studies/
└── week-01/
    ├── README.md              # 이번 주 주제 & 권장·선택 문제
    ├── gildong/               # 각자 깃허브 ID로 폴더 생성
    │   ├── 권장1-프로그래머스-키패드누르기.md
    │   ├── 권장2-프로그래머스-신고결과받기.md
    │   ├── 선택1-프로그래머스-모의고사.md
    │   └── ...                # 선택 5문제까지
    └── younghee/
        └── ...
```

- 본인 폴더 이름은 **깃허브 아이디**로 통일합니다. (충돌·헷갈림 방지)
- 한 문제 = 한 파일(`.md`). 코드는 본문 안 코드블록에 포함합니다.

### 파일 이름 규칙
```
<구분>-<플랫폼>-<문제이름>.md
```
- `<구분>`: `권장1`, `권장2`, `선택1` ~ `선택5`
- `<플랫폼>`: `프로그래머스` / `백준` / `SWEA` / `LeetCode` 등
- 예) `권장1-프로그래머스-키패드누르기.md`, `선택1-백준1920-수찾기.md`, `선택2-LeetCode-TwoSum.md`, `선택3-SWEA-1954-달팽이숫자.md`
- **선택 문제는 플랫폼 자유** — 같은 유형이면 어디서 풀든 OK. 파일명에 플랫폼을 표기하세요.
- 공백 대신 붙여쓰거나 `-` 사용. 특수문자는 피합니다.

## 2. 풀이 작성법 — 5요소 필수

모든 풀이는 [`templates/SOLUTION_TEMPLATE.md`](../templates/SOLUTION_TEMPLATE.md)를 복사해 작성하며, 아래 5가지를 **반드시** 포함합니다.

1. **접근 방법** — 문제를 어떻게 이해하고 어떤 전략을 택했는가
2. **시간 복잡도** — Big-O와 그 근거
3. **공간 복잡도** — Big-O와 그 근거
4. **핵심 풀이 방법** — 이 문제의 결정적 아이디어 (여기가 제일 중요!)
5. **실제 코드** — 제출·통과한 코드

> 💡 사용 언어는 자유(Python/Java/C++/JS 등). 코드블록에 언어를 명시하세요( ` ```python ` ).

## 3. 작업 흐름 (Git)

> 협업은 **브랜치 → PR → 리뷰 → 머지** 흐름을 권장합니다. 소규모라면 개인 브랜치만 지켜도 충분합니다.

```bash
# 0) 최초 1회: 커밋 템플릿 등록
git config commit.template .gitmessage

# 1) 최신화
git switch main
git pull

# 2) 작업 브랜치 생성 (규칙: week/<주차>/<깃허브ID>)
git switch -c week/01/gildong

# 3) 풀이 작성 후 커밋 (템플릿에 맞춰)
git add studies/week-01/gildong
git commit          # 편집기에 커밋 템플릿이 뜸

# 4) 푸시 & PR
git push -u origin week/01/gildong
# GitHub에서 PR 생성 → PR 템플릿 자동 표시 → 작성 → 리뷰 요청

# 5) 리뷰 1명 이상 후 머지 (마감 전까지)
```

### 브랜치 이름 규칙
```
week/<두자리주차>/<깃허브ID>     예) week/01/gildong
```

## 4. 커밋 메시지 규칙

커밋 템플릿([`.gitmessage`](../.gitmessage))을 등록하면 아래 형식이 자동으로 뜹니다.

```
<타입>: <제목>

예) solve: [W01] 프로그래머스 신고 결과 받기
```

| 타입 | 의미 |
|:---|:---|
| `solve` | 문제 풀이 추가 |
| `fix` | 풀이 수정 / 오답 정정 |
| `refactor` | 로직 동일, 코드 정리 |
| `docs` | 문서(자기소개·README 등) 수정 |
| `chore` | 설정·기타 |

**규칙**: 제목 50자 이내 · 마침표 없음 · 명령형.

## 5. PR 규칙

- PR 제목: `[W01] gildong - 권장 2 + 선택 5` 처럼 **주차 + 이름 + 내용** 요약
- 본문은 [PR 템플릿](../.github/PULL_REQUEST_TEMPLATE.md)의 체크리스트를 채웁니다.
- **리뷰 1명 이상 승인/코멘트 후 머지.**
- 마감(일 23:59) 이후 머지된 PR은 해당 주차 미완료로 집계될 수 있습니다.

## 6. 자기소개 등록

1. [`members/_TEMPLATE.md`](../members/_TEMPLATE.md)를 복사 → `members/<깃허브ID>.md`
2. 내용 작성 후 [`members/README.md`](../members/README.md) 표에 한 줄 추가
3. 커밋: `docs: <깃허브ID> 자기소개 추가`

## 7. 자주 묻는 질문

**Q. 권장 문제를 못 풀겠어요.**
A. 30분~1시간 고민 후에도 막히면, 풀이를 찾아보고 **"핵심 풀이 방법"에 무엇을 몰랐는지** 정리하세요. 이해하고 넘어가는 것이 목표입니다. (단, 완전 복붙 금지 — 반드시 5요소를 본인 언어로 서술)

**Q. 선택 문제는 어디서 고르나요? 꼭 5개인가요?**
A. 주차 README의 **선택 풀**에서 고르거나, **원하는 플랫폼(프로그래머스·백준·SWEA·LeetCode 등)에서 같은 유형이면 자유 선택**하세요. 목표는 **주 5개**(권장 2 + 선택 5 = 하루 1문제 페이스), 벌금 하한은 3개입니다. 벅차면 쉬운 유사 문제로, 여유 있으면 한 단계 위로.

**Q. 다른 언어로 풀어도 되나요?**
A. 네. 코드블록 언어만 정확히 표기하세요.
