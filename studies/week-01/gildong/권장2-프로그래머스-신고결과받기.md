## 1. 접근 방법
각 유저가 "누구를 신고했는가"와 "몇 번 신고당했는가"를 알아야 한다.
- 같은 사람이 같은 사람을 여러 번 신고해도 **1회로 처리** → 신고 관계는 **중복 제거(집합)** 로 저장.
- `k`번 이상 신고당한 유저는 정지되고, 그 유저를 신고한 사람들에게 메일이 간다.

처음엔 신고 문자열을 매번 순회하며 세는 방법(O(신고수 × 유저수))을 떠올렸지만,
**"신고당한 횟수"를 딕셔너리로 한 번에 집계**하고, **"내가 신고한 사람"을 유저별 집합으로** 들고 있으면
마지막에 각 유저가 신고한 사람 중 정지된 사람 수만 세면 되어 훨씬 깔끔하다.

## 2. 시간 복잡도
**O(R + U·R')** — R = 신고 기록 수, U = 유저 수, R' = 유저당 평균 신고 수.
- 신고 집계: 중복 제거된 신고 관계 순회 O(R)
- 결과 계산: 각 유저가 신고한 목록을 훑으며 정지 여부 확인 → 전체 합이 O(R)
- 사실상 **O(신고 수)** 수준.

## 3. 공간 복잡도
**O(U + R)** — 유저별 신고 목록(집합) 저장 O(R), 신고당한 횟수 딕셔너리 O(U).

## 4. 핵심 풀이 방법 ⭐
- **중복 신고 제거**가 첫 번째 함정: `report`를 `set`으로 감싸 유일한 신고 관계만 남긴다.
- 두 개의 자료구조로 분리해서 생각하면 쉬워진다.
  - `reported_by[신고한사람] = {신고한 대상들}`
  - `count[신고당한사람] += 1`
- 마지막에 각 유저에 대해, 자기가 신고한 사람들 중 `count >= k` 인 사람 수를 합산 → 메일 개수.
- `id_list` 순서대로 결과를 반환해야 하므로 유저 인덱스 매핑을 유지한다.

## 5. 실제 코드
```python
def solution(id_list, report, k):
    reported_by = {uid: set() for uid in id_list}  # 내가 신고한 사람들
    count = {uid: 0 for uid in id_list}            # 신고당한 횟수

    for r in set(report):            # 중복 신고 1회 처리
        reporter, reported = r.split()
        reported_by[reporter].add(reported)
        count[reported] += 1

    banned = {uid for uid in id_list if count[uid] >= k}

    return [sum(1 for t in reported_by[uid] if t in banned) for uid in id_list]
```

### 🧠 회고
- "중복 제거 → 집계 → 조건 판정" 3단 구조는 해시 기반 카운팅 문제에서 반복적으로 재사용된다.
- `set(report)`로 중복을 없애는 한 줄이 이 문제의 승부처였다.
